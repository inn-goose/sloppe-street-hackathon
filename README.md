# Sloppe Street — a forecasting agent for *Agents vs Wall Street*

Forecasts twelve reported financial figures — three each for Home Depot, Analog Devices,
Hays plc and Deere & Company — and writes the four OpenStocks submission workbooks.

```bash
python -m code.run all          # fetch → extract → feature → model → four .xlsx
```

The submitted numbers are in [`submission/`](submission/). Every one of them is traceable to the
filing sentence it came from, the anchor that produced it and the backtest that chose that anchor.

---

## What this repository does and does not contain

⛔ **The document corpus is not here, and must not be.** The 1,139 filings, transcript sections and
slide decks live in the competition's own repository under `challenge/offline-data/`. Its
`THIRD_PARTY_NOTICES.md` is explicit: *"Their inclusion here does not grant a licence to republish
or commercially redistribute them."* So this project reads them from a **separate checkout** and
never copies them into version control.

```bash
git clone https://github.com/kernlai/agents-vs-wall-street-starter.git starter
# or point anywhere you like:
export CHALLENGE_CORPUS=/path/to/agents-vs-wall-street-starter/challenge/offline-data
```

`data/` is ignored for the same reason plus one more: it is entirely regenerated by the command
above, and `data/raw/corpus/` would otherwise hold 1,140 verbatim copies of those licensed filings.
Nothing in `data/` is an input this repository is missing.

What *is* here: the four workbook templates and `companies.json` (MIT, © 2026 OpenStocks — see
[`LICENSE.openstocks`](LICENSE.openstocks)), all the code, the settings, and the completed
workbooks.

## The pipeline

Four layers, and the borders between them are load-bearing.

```
  raw/          verbatim source bytes, banked with an as-of stamp and never rewritten
    ↓
  extracted/    one row per fact a document actually states — no fills, no opinions
    ↓
  feature/      joins across lanes; every column computable at every past period
    ↓
  model/        chooses how to forecast, out of sample, then writes the workbooks
```

| stage | command | what it produces |
|---|---|---|
| fetch | `python -m code.run fetch` | `data/raw/` — 9 providers, verbatim |
| extract | `python -m code.run extract` | `data/extracted/` — typed facts |
| feature | `python -m code.run feature` | the reconciled panel and the training matrix |
| model | `python -m code.run model` | the twelve forecasts and four `.xlsx` |

⚠️ **`fetch` is the only stage that reaches the network.** Everything after it is a pure function of
banked bytes, which is why the final run can be executed with the network unplugged and why a rerun
reproduces the same numbers.

### The border that matters most

The feature layer emits **series, never forecasts**. Every column of `training_matrix.parquet` is
computable at every historical period from data published before it, and the twelve target rows are
built by the same loop as the training rows so no column can be computed one way in training and
another at prediction.

⛔ **A rule that produces a value only for the target period cannot be validated at all**, and its
parameters end up being set by eye against whatever the number is compared to — which, here, is the
benchmark being competed against. Every forecasting rule in this repository therefore has a history
and is scored on it.

## How a forecast is actually chosen

Each target carries several independent **anchors** — a guide midpoint, an annual guide split by a
measured seasonal share, a companion line times its historical ratio, a momentum carry, last year's
same quarter. Each is a legitimate forecast on its own.

`code/model/train.py` runs a walk-forward backtest over seven expanding folds, cut on the date each
figure was *published*, and scores every strategy on the competition's own rule. Ten strategies were
compared; the winner is the simplest:

> **take the anchor whose type has the smallest residual dispersion on that metric's own history,
> and submit it — with one exception.**

The exception is the guide midpoint, which is shifted by the median amount filers have historically
cleared their own guides. That is worth `t = −2.21` out of sample and is the one deliberate
deviation, because submitting a midpoint scores about 1.0 by construction: it is where the sell side
already sits.

⚡ **The gradient-boosted model's contribution was to prove a correction was not needed.** LightGBM
on the pooled anchor residuals is clearly better than leaving anchors alone (median normalised error
0.125 against 0.151) — it repairs a naive momentum carry by 1.47×. But those are the anchors a row
is *not* forecast from. On the anchors that win selection it is actively harmful: the seasonal
split's error goes from 0.0625 to 0.0990 under correction. A good anchor is already calibrated. The
model is kept in the pipeline because that is how the finding is reproduced, not because it moves a
submitted number.

## Checks that run every time

| check | what it refuses |
|---|---|
| `feature/check_panel` | 16 values hand-read from the filings must match the panel — currently 16/16 |
| `feature/audit` leakage | nothing published after the deadline may reach any row |
| `feature/audit` additivity | four quarters must sum to the filer's own annual total |
| `feature/audit` calendar | 52- vs 53-week fiscal years, measured year-end to year-end |
| panel containment | a period may not be smaller than a period inside it |
| workbook writer | metric labels matched exactly; a mismatch stops the run |

Each is arithmetic on the filers' own numbers, so none of them needs a judgement call: four quarters
either reach the stated year or they do not, and a half cannot exceed the year containing it. Where
a check fails, the panel records the refusal rather than repairing past what the evidence supports —
`data/feature/ladder_repairs.parquet` and `containment_repairs.parquet` carry every one.

## Layout

```
code/provider/<name>/fetch/     banks data/raw/, verbatim and as-of
code/provider/<name>/extract/   derives data/extracted/, faithful
code/feature/                   panel, guides, seasonality, training matrix
code/model/                     dataset → train → predict → workbooks
code/lib/                       store, raw-store grammar, text grammar, settings
code/vendor/                    declared pre-existing components (see its README)
challenge/templates/            the four supplied workbook templates
submission/                     the four completed workbooks
```

`code/vendor/` holds generic library code written before the event and declared in `entry.json`, as
`RULES.md` requires. Everything company-specific — every reader, feature, anchor, validator and the
model itself — was built during the event.

## Requirements

Python 3.14, and:

```bash
pip install -r requirements.txt
```

`pyarrow` for the store, `numpy` for the model matrices, `lightgbm` for the gradient-boosted
residual model, `openpyxl` to write the workbooks. On Apple Silicon LightGBM also needs the OpenMP
runtime (`brew install libomp`).

Credentials are read **by environment-variable name only** and never stored in this repository:
`APCA_API_KEY_ID` / `APCA_API_SECRET_KEY` for Alpaca, and a contact string in `SEC_USER_AGENT` for
the SEC's fair-access policy. Every other provider is keyless. Without them the `fetch` stage skips
those lanes; the rest of the pipeline runs from whatever is already banked.
